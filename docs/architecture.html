Data flow: a typical task

  1. User sends prompt to Claude Code
    • UserPromptSubmit fires: correction-signal + completion-claim detectors run
    • If correction matched → -2.0 reward event in rewards.jsonl
    • If completion claim → nudge to /verify injected as additionalContext
  2. Claude works (Read/Edit/Write/Bash/Agent)
    • PreToolUse(Bash) on git commit → critic on staged diff; CRITICAL exits 2 (block); HIGH warns
    • PostToolUse(Edit|Write) on agent .md → debounced /eval queued
  3. Claude marks task complete
    • TaskCompleted: if RESULT_verifier=PASS exists in session → pass; FAIL/INCONCLUSIVE → surface, exit 2; no evidence → spawn verifier headlessly
    • emit_task_reward.py: greps session JSONL for RESULT_*, writes events to rewards.jsonl
  4. Session ends
    • log-cache-stats.sh: append cache-stats record (anomaly flag if <70%)
    • emit_session_rewards.py: aggregate per-agent, recompute value/<agent>.json

Why these design choices

Why prompt-only RL (no fine-tuning)?

We don't have weight access to Claude. The available levers are:

  • Reflexion = prompt update via /tune-agent
  • Best-of-N + critic = test-time scaling
  • A/B test + promotion = policy gating
  • Reward modeling = scoring future runs by past patterns

Each is API-compatible. Together they're the production-realistic RL stack for closed-source LLMs.

Why markdown + grep instead of vector DB?

At hundreds-to-thousands of memory entries:

  • BM25/grep is sub-ms latency, zero GPU cost, exact-match for technical content
  • Curation quality dominates retrieval algorithm at small scale (HippoRAG/Mem0/Zep)
  • Real wins are write-time policy: A-MEM linking, Zep validity, Mem0 ADD/UPDATE — these improve the index

See arXiv 2501.01880 — Long Context vs RAG.

Why aspect-panel instead of multi-round debate?

Per arXiv 2502.08788 ("Stop Overvaluing MAD") and 2509.05396, multi-round debate at rounds 4+ measurably hurts. Real gains come from:

  • Heterogeneous personas (ChatEval)
  • Confidence-weighted aggregation (ReConcile, Beyond Majority Voting)

/aspect-panel does both. We do not do multi-round debate.

Why no hierarchical agent structure?

Per arXiv 2509.10769, hierarchical beats flat only at >10 agents. We have ~20 but most invocations involve 3–5. Flat with a lead is correct.

Why AggAgent (synthesize) over argmax?

Per arXiv 2604.11753, when rollouts contain complementary insights, synthesizing a NEW answer that merges the best of all N beats picking the best single one. Used for design docs, multi-step reasoning, deep research.

For tasks with one correct answer (specific bug fix, specific test) keep --mode critic.

Why hooks-as-guarantees over CLAUDE.md rules?

CLAUDE.md is suggestions; hooks are enforcement. auto-verify-on-complete can't be forgotten. auto-critic-on-commit can't be skipped. Determinism belongs in the harness, not the prompt.

Limitations (honest)

  1. No fine-tuning — Reflexion is a prompt-level operation. Real SOTA in academic terms requires weight access.
  2. Reward sparsity — most tasks don't generate strong signal. Baseline +0.1 keeps the value function moving.
  3. Auto-verify cost — every TaskCompleted with no prior evidence triggers ~$0.10 headless run. Mitigated by trivial: bypass.
  4. No cross-machine sync — ~/.claude/rl/ is local. Future: sync via git or cloud.
  5. Reward hacking — agents could in principle learn to skip work to avoid critic findings. Mitigation: verifier reward dominates and requires real PASS evidence in JSONL — can't fake.
  6. Subscription rate limits — auto-firing hooks consume the same quota as manual usage. Set ANTHROPIC_API_KEY for --bare mode if you hit ceiling.
