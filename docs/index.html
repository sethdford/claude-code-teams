What this is

A drop-in upgrade for ~/.claude/ that makes the difference between orchestration and verifiable, self-improving delivery.

⚙

Composed, not invented

Every component traces to a published technique. AggAgent synthesis ([2604.11753]). Universal Self-Consistency ([2311.17311]). Mano-verify multi-modal ([2509.17336]). A-MEM Zettelkasten ([2502.12110]). Plus Anthropic's official sandbox-runtime, Agent Skills, and the canonical Claude Code primitives.

🛡

Verified, not asserted

Every "task done" runs through a verifier agent that runs the code in an OS-level sandbox. Every sprint runs through a separate adversarial auditor. Every committed change runs through a 5-aspect verifier panel with confidence-weighted voting. Failure modes are caught, not glossed.

📈

Measured, not hyped

Reward telemetry on every agent. Cache hit-rate dashboards. A/B-tested prompt evolution. Trajectory mining that turns past sessions into rule patches. The system knows whether it's actually working — which is the difference between architecture and SOTA.

The stack

Six layers, all native primitives.

01

Orchestration

/scrum runs the full SDLC ceremony: Product Owner → Tech Lead → Scrum Master → parallel implementers → Verifier → Aspect-Panel → Sprint Auditor → Retro. /team for ad-hoc fleets. /spec for Kiro three-file design.

  • product-owner, tech-lead, scrum-master, sprint-auditor
  • 12 domain specialists: security-reviewer, migration-planner, regression-hunter, latency-profiler, …
  • Native Agent + TaskCreate + worktree isolation
02

Verification

Verifier agent runs code in OS-level sandbox (sandbox-exec on macOS, bwrap on Linux). 5-aspect panel votes confidence-weighted. Sprint Auditor independently re-checks ACs against actual code state — adversarial.

  • /verify · spawn verifier, capture evidence, RESULT_verifier=PASS|FAIL|INCONCLUSIVE
  • /aspect-panel · 5 specialized verifiers, ESCALATE on 40-60% disagreement
  • /verify-ui · Mano-verify pattern (pre/post screenshots + intent → vision judge)
03

Test-time scaling

Best-of-N with five aggregation modes — argmax critic, USC consistency, confidence-weighted, hybrid, and AggAgent synthesis (merge across rollouts). Execution-grounded BoN runs each candidate in a sandboxed copy and scores by actual test pass rate.

  • /best-of-n --mode synthesize · AggAgent (+5-10% per arXiv 2604.11753)
  • /exec-grounded · candidates judged by green tests, mirrors SWE-bench leaders' 60-80% verification compute
04

RL telemetry

Every TaskCompleted, UserPromptSubmit, and SessionEnd emits reward events. Per-agent value functions accumulate. Recurring failures trigger Reflexion patches; A/B test gates promotion.

  • rewards.jsonl · append-only event log
  • value/<agent>.json · rolling 7d/30d mean reward + stderr
  • /tune-agent · Reflexion patch from ≥2 failures
  • /ab-test · candidate vs current with promotion gating
05

Memory

A-MEM Zettelkasten linking. Zep-style temporal validity (mark superseded, don't delete). Karpathy-style structured index — beats vector retrieval at our scale per published benchmarks.

  • knowledge/{concepts,connections,qa}/ · auto-bidirectional linking
  • lessons.md · valid_from / superseded_by fields
  • /mine-transcripts · Haiku-extracts patterns from past JSONL → proposes diffs
06

Auto-fire

Hooks wired into every Claude Code lifecycle event. Verifier auto-spawns on TaskCompleted. Critic auto-runs before commit. Constitutional gate guards destructive ops. Eval auto-queues on agent edits. The user never has to remember.

  • SessionStart × 2 · PreCompact · SessionEnd · TaskCompleted
  • UserPromptSubmit · PreToolUse(Bash) · PostToolUse(Edit|Write)
  • 3 persistent scheduled tasks · daily cache-report · weekly mining + rl-status

End-to-end proof

The adversarial audit is the load-bearing piece.

Most agent stacks claim "verified" but trust the team's own evidence. Ours doesn't. The Sprint Auditor independently re-derives whether each acceptance criterion was delivered — without trusting the team's claims. Drift detection has teeth.

Install

One command. Symlinked, idempotent, reversible.

1

Clone & install

$ git clone https://github.com/sethdford/claude-code-teams.git
$ cd claude-code-teams
$ ./install.sh
2

Merge settings.json (manual, never auto-overwrites)

$ diff ~/.claude/settings.json ~/.claude/settings.json.template
# merge in: hooks, statusLine, env keys
3

Restart Claude Code & verify

$ ./tests/smoke.sh
✓ 77 passed, 0 failed
$ ./tests/scrum_smoke.sh
✓ 13 passed, 0 failed
4

Try a real run

$ claude -p "/scrum 'add OAuth login per spec.md'"
